# Бибип: файловая база данных на Python

Решены все семь заданий проекта: добавление моделей и автомобилей, продажа,
фильтрация по статусу, получение полной информации, исправление VIN,
отмена продажи и топ-3 моделей.

## Запуск в Windows PowerShell

Нужен Python 3.11 или новее. Проверено на Python 3.14.7.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
```

В Linux/macOS используйте `.venv/bin/python` вместо пути к Windows-интерпретатору.
Настройка `pytest.ini` добавляет `src` в путь импорта. Тесты создают отдельную
временную базу для каждого сценария.

## Пример

В Python с каталогом `src` в PYTHONPATH:

```python
from datetime import datetime
from decimal import Decimal
from bibip_car_service import CarService
from models import Car, CarStatus, Model, Sale

service = CarService("data")
service.add_model(Model(id=1, name="Optima", brand="Kia"))
service.add_car(Car(
    vin="KNAGM4A77D5316538", model=1, price=Decimal("2000"),
    date_start=datetime(2024, 2, 8), status=CarStatus.available,
))
service.sell_car(Sale(
    sales_number="01#1", car_vin="KNAGM4A77D5316538",
    cost=Decimal("2500"), sales_date=datetime(2024, 3, 1),
))
print(service.get_car_info("KNAGM4A77D5316538"))
print(service.top_models_by_sales())
service.revert_sale("01#1")
```

Повторное добавление тех же ключей вызывает ValueError. Пример запускается на
новом каталоге; существующие данные сохраняются между запусками.

## Устройство хранения

- `cars.txt`, `models.txt`, `sales.txt`: JSON-записи UTF-8, дополненные пробелами
  до 500 **байт**, плюс один байт LF. Бинарный режим исключает преобразование LF
  в CRLF в Windows. Адрес записи — номер строки × 501. Слишком длинная запись
  отклоняется до изменения файлов.
- Индексы `*_index.txt`: JSON-строки `[ключ, номер_строки]`, отсортированные по
  ключу (VIN/номер продажи — строки; id модели — целое число).
- Индексы загружаются в память; данные читаются по одной записи через seek
  или генератор. В памяти остаются только результат списочного метода и
  агрегаты по моделям, а не все исходные таблицы.
- Продажа меняет статус машины на sold. Отмена продажи оставляет пустой блок
  на прежнем месте и удаляет ключ из индекса: позиции других записей сохраняются.
  Статус машины возвращается в available.
- Смена VIN перестраивает индекс автомобилей и сохраняет ссылки в продажах.
- Первичный ключ продажи — sales_number; исправлен метод Sale.index в шаблоне.
- При одинаковом количестве продаж модели сравниваются по средней цене продажи,
  затем по id для однозначного порядка. Несостоявшиеся сделки не учитываются.
- Поля CarFullInfo и ModelSaleStats сохранены из исходного интерфейса:
  car_model_name, car_model_brand и sales_number (количество продаж).

## Тесты и отличие от шаблона

Исходный запуск: 7 ошибок NotImplementedError.
После реализации: 14 успешно пройденных тестов.

В исходном test_list_cars_by_available_status ожидался порядок добавления,
но задание 3 явно требует сортировку по VIN. Ожидание исправлено на
sorted(available_cars, key=lambda car: car.vin), без удаления проверки.
В тесте добавления пустое assert True заменено реальной проверкой чтения.

Дополнительные тесты проверяют сохранение после повторного открытия, кириллицу,
Decimal, дубликаты, отсутствующие ссылки, повторную продажу, отмену средней
записи, исправление VIN проданного автомобиля, ранжирование и лимит записи.

Зависимости шаблона обновлены для установленного Python 3.14; версии зафиксированы
в requirements.txt. Для Python 3.11+ используется тот же интерфейс Pydantic v2.

## Ограничения учебной реализации

Один активный экземпляр CarService на каталог, без конкурентных писателей.
Нет журнала транзакций и восстановления после аварии между изменениями разных
файлов. Операции с несколькими файлами не гарантируют атомарность при отключении
питания. Удалённые блоки не уплотняются. Это учебная модель индексов и файловых
операций, а не промышленная СУБД.
